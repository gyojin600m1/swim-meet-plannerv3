# 水泳エントリー確認アプリ 作成マニュアル

作者：gyojin600m1（鹿児島／宮崎の水泳大会向け）。読む人は**選手と保護者**。会場でスマホから見る。

作業方針：質問で確認を取らずに、いきなり完成品（単一HTMLファイル）を出す。
候補を並べる・出来の良し悪しを自己評価する・使い方の長い説明を添える、はどれも不要。

---

## 0. 受け取るもの／やること

| 受け取るもの | やること |
|---|---|
| エントリー表のURL（またはスクショ・貼り付けテキスト） | ① エントリー確認アプリ（単一HTML）を作る → ② GitHubに上げる手順を出す → ③ Notionに1行足す |
| 後日、結果のURL | ④ 同じアプリに結果を組み込んだ **全文の新しい index.html** を出す |

## 1. 最初に必ず確認すること（飛ばさない）

1. **転載禁止の掲示チェック。** データ元のページに「大会運営以外の目的での転載・再利用・加工・再配布はご遠慮ください」等の掲示があるか必ず見る。
   - 掲示**あり** → **公開アプリは作らない**。「掲示があったので公開はやめます。手元だけで見る版にしますか？」と一言だけ返して止まる。
   - 掲示**なし** → 通常どおり作る。掲示は大会ごとに出るので、毎回見ること。
2. **数の検算。** 公式ページの合計エントリー数・組数と、抽出した件数が合うか必ず突き合わせてから出す。合わないときは合わない旨を書く（黙って出さない）。
3. URLが取得できない／PDFが読めないときは、その旨を1行で言う。スクショかテキストをもらう。

## 2. アプリの仕様（毎回これで作る。省略しない）

### 2-1. 形
- **単一のHTMLファイル1本**（ファイル名は必ず `index.html`）。CSS・JS・データを全部その中に埋め込む。
- **実行時 fetch は使わない**（データはJSの配列/JSONとして直書き）。ネット無しでも、ファイルを直接開いても動くこと。
- 「Claudeアプリで開く」系の案内・App Storeボタンは**絶対に入れない**。誰のブラウザでも普通に開けること。
- 画面の最後に「**非公式アプリです。記録は速報値です。**」の一文。
- **データの出典元の団体名は画面に書かない**（承諾を得て載せているように見えるため）。会場名・日付はOK。

### 2-2. 男女色分け（必須要件。毎回入れる）

```css
--male:#1565c0;  --female:#b71c6e;          /* チップ・タグの背景 */
--maleText:#6fb7ff; --femaleText:#ff92c2;  /* 暗い背景の見出し文字 */
--maleBg:#12325d;  --femaleBg:#4a1030;     /* バッジの淡い背景 */
```

- 男女フィルタは `🔵 男子` `🔴 女子` の絵文字つきチップ、選択中は各色で塗る
- 選手カード・行の**左に5pxの縦ライン**、氏名の右に丸い `男子`/`女子` タグ
- 種目見出し・名簿の見出しにも色と🔵🔴
- 所属別の名簿は**男女ブロックに分ける**（混ぜない）

### 2-3. スマホ優先
- **375px と 320px で横スクロールが出ないこと。** 表(table)よりカードを使う。どうしても表なら横スクロール枠で囲む。
- タップ領域は48px以上。検索欄は画面上部に固定でもよい。
- タブは3〜4個まで。ダークでも明るい画面でも読める配色に。

### 2-4. タブ構成（標準形）
1. **選手をさがす**（名前・所属で検索。1文字目から絞り込み）
2. **種目別**（種目→エントリー一覧。タイム順）
3. **所属・学校別**（男女ブロック分け）
4. **プログラム**（競技No.順。組・レーンが公表されていれば表示）

### 2-5. 検索の作法
- ひらがな入力は「入れられる範囲で」。ふりがなデータが無いときは**漢字・所属名の一致だけで良い**。
- **推定した読みを画面に表示しない**（子どもの名前に誤ったふりがなを付けることになるため）。検索欄の下に「ひらがなOK」等と書くのも、実際に効かないなら書かない。
- **リレーだけ出場の選手を落とさない。** リレー行の泳者名4名も名前検索のキーに必ず入れる（これを忘れると100人以上が検索に出てこない）。

### 2-6. 組・レーンが未発表のとき（予想を出す場合の固定ルール）
- 全体をタイム順に並べ、**遅い方から組を切る**（第1組＝いちばん遅い、最終組＝いちばん速い）。組の中は**速い順**。
- レーンは速い順に **10レーン: 4→5→3→6→2→7→1→8→0→9** ／ **8レーン: 4→5→3→6→2→7→1→8**
- 端数：余り0＝全部フル、**余り1＝3人+8人+10人…**（1人組は作らない）、余り2以上＝端数を先頭の組に。
- 予選とタイム決勝だけ。決勝・B決勝・リレーには使わない。**必ず「予想」と明記する。**

### 2-7. 閲覧カウンター（公開する場合のみ）

```js
const NS = "gyojin600m1-" + <リポジトリ名>;   // アプリごとに変える
const KEY = "views";
// 1日1回だけ https://abacus.jasoncameron.dev/hit/{NS}/{KEY}、2回目以降は /get/{NS}/{KEY}
// localStorageの日付スタンプのキーは必ず "viewCounterStamp:"+NS+":"+KEY （NSを含めないと1日1アプリしか数えない）
// fetch失敗・404ならバッジは非表示にするだけ（本体に影響させない）
// CSPを書くなら connect-src に https://abacus.jasoncameron.dev を追加
```

表示は「👀 のべ閲覧 ◯回」。`border:1px solid currentColor; opacity:.7` の小さいバッジ。

## 3. GitHubに上げる手順（iPhoneのSafariでできる形で出す）

アカウントは **gyojin600m1**。公開URLは必ず `https://gyojin600m1.github.io/<リポジトリ名>/` になる。
リポジトリ名は英小文字ハイフン区切りでこちらが決めてよい（例：`kagoshima-xx-swim-2026`）。

手順は、この通りに書く（指で操作するため）：

1. `github.com/new` → Repository name に `<リポジトリ名>` → **Public** → Create repository
2. 「creating a new file」をタップ → ファイル名に `index.html` → 本文にアプリのコードを貼り付け → Commit changes
   - コードが長くて貼れないときは、**アーティファクトをダウンロード→「ファイル」アプリに保存→ Add file → Upload files** の順で（このときファイル名が `index.html` になっているか確認）
3. Settings → Pages → Branch: **main** / **/(root)** → Save
4. 2〜3分待って `https://gyojin600m1.github.io/<リポジトリ名>/` を開いて確認

**更新するとき**：リポジトリ → `index.html` → 鉛筆マーク → 全選択して新しいコードに置き換え → Commit changes（1〜2分で反映）。

## 4. Notionへの載せ方（厳密に）

ハブページ：**「鹿児島水泳エントリー検索！随時更新！」**

- **リンク1行を、既存の行と同じ体裁で追加するだけ。**
- 使い方・特徴・注意書き・見出し・箇条書きを**勝手に足さない**。ここはシンプルに保つ。
- 宣伝文が要るときは、Notionに書かずに**チャットに文案を出す**（Instagram用）。

Notionコネクタが使えないときは、貼る用のテキスト1行だけ出す。

## 5. 結果が出たあと（結果URLをもらったら）

同じアプリに結果を**組み込む**（別アプリを新規に作らない）。

- タイトルとサブタイトルを「**大会結果＋エントリー確認**」に変え、**既定タブを 🏅結果 にする**。
- 結果は**選手カードの種目行にインラインで出す**（別タブに隔離しない）。種目別・リレーのカードにも同じく。
- **順位は種目全体の順位を使う**（組内順位をそのまま出さない）。
- 表彰の表示：**個人は1〜6位、リレーは1〜3位**。1〜3位は 👑 金・銀・銅、4〜6位は水色の「入賞」チップ、7位以下は素の順位。
- **失格・棄権の行を絶対に落とさない**（順位欄が空の行を捨てる実装にしない）。「失格」「棄権」として表示する。同着はタイム一致で確認できる。
- 自己ベスト更新が判るデータがあれば ⭐ などで印を付ける。
- 検算：件数＝入賞件数＋その他、順位とタイムの矛盾ゼロ、順位なし件数＝棄権＋失格、を確認してから出す。
- 出力は**差分ではなく、新しい `index.html` の全文**。

## 6. やらないこと

- 転載禁止の掲示がある大会の公開アプリを作る
- 男女色分けを省く／スマホで横スクロールする表を出す
- 実行時fetchでデータを取りに行く作り
- 画面にデータ元の団体名を書く
- Notionに説明文を足す
- 「どちらにしますか？」と選ばせる（決めて完成品を出す）
- 出来栄えの自己評価を書く
